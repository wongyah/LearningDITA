# 块元素和行内元素

关于 XML，你学到的第一点大概就是内容与格式分离吧?

不过，偶尔，DITA、XML 和 HTML 中的内容也会"内置"一点点格式。块元素和行内元素这两个概念就是其中的一个例子：

**块元素**是指段落级别的元素，例如段落（`<p>`）、无序列表（`ul`）、有序列表（`ol`）或代码块（`<codeblock>`）。一般来说，块元素会占据整个行宽。块元素前面的内容位于它的上方，块元素后面的内容位于它的下方。所以，如果你在一行中连续插入两个 `<p>` 元素，在预览模式或最终生成的文档中这两个元素中的内容并不会直接连在一起。它们之间会被自动插入一个换行符，形成两个段落。你得知道，在XML文件中无论插入多少换行符，都不会对最终生成的文档格式产生任何影响。

```xml
<p>这是第一段内容。</p><p>这是第二段内容。</p>
```

在 Oxygen XML 编辑器的写作模式下或者在生成的文档中，上面代码通常显示为以下格式：

--8<-- "sample_snippet.md:start"
这是第一段内容。

这是第二段内容。
--8<-- "sample_snippet.md:end"

**行内元素**是指位于段落内的元素，比如粗体（`<b>`）、斜体（`<i>`）、交叉引用（`<xref>`）或术语（`<term>`）。默认情况下，行内元素不会引起换行。

```xml
<p>行内元素<i>不会</i>引起换行。</p> 
<p>XML 中的换行符
      <i>不会</i>
对文档格式产生任何影响。</p>
```

在 Oxygen XML 编辑器的写作模式下或者在生成的文档中，上面代码通常显示为以下格式：

--8<-- "sample_snippet.md:start"
行内元素*不会*引起换行。

XML 中的换行符*不会*对文档格式产生任何影响。
--8<-- "sample_snippet.md:end"

XML 本身并不区分块元素和行内元素，它们的标签格式都是相同的。你只能记住哪些元素是块元素，哪些元素是行内元素，才能对内容的最终格式有一个基本的判断。内容编辑软件一般都有自动验证功能，可以对 DITA 的内容结构自动进行合法性验证。如果你插入的元素不对，就会收到错误提示。

行内元素相当于 Word 软件中的字符样式。只是，有些行内元素和 Word 软件中字符样式不太一样，比如脚注（`<fn>`）和术语索引（`<indexterm>`）。例如，`<indexterm>` 元素中的内容不会显示在当前位置，而是在文档的末尾生成一条的索引。

```xml
<p>行内元素<indexterm>行内元素</indexterm><i>不会</i>引起换行。</p>
```
