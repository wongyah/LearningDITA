# 插入操作流程

编写操作流程的常用元素有 `<steps>`、`<step>`、`<cmd>` 和 `<info>`等。

`<steps>`
: 一组分步骤的操作说明。一个 `<steps>` 元素中可以包含一个或多个 `<step>` 元素。

`<step>`
: 单个操作步骤。每个操作步骤中能且只能包含一个 `<cmd>` 元素。在 `<step>` 元素中，也可以包含 `<info>` 元素以及其他可以为操作步骤提供额外信息的元素（这些元素将在本节课的后续部分介绍）。

`<cmd>`
: 一条指令。每个 `<cmd>` 元素中应该只写一个句子，而且要使用主动语态。

`<info>`
: 与该操作步骤有关的其他信息。

## 随堂练习

1. 打开上一讲使用的练习文件 `l_task_start.dita`。

2. 在 `<context>` 元素的后面，插入一个 `<steps>` 元素。

    ```xml
    <?xml version="1.0" encoding="UTF-8"?>
    <!DOCTYPE task PUBLIC "-//OASIS//DTD DITA Task//EN" "task.dtd">
    <task id="my_first_task">
      ...
        </context>
        <steps>
        </steps>
      </taskbody>
    </task>
    ```

    一个 `<taskbody>` 元素中只能包含一个 `<steps>` 元素，和 `<prereq>`、`<context>` 元素一样。将 `<steps>` 元素的数量限制为一个，可以确保每个主题中只包含一项任务的操作方法。

3. 在 `<steps>` 元素中，插入一个 `<step>` 元素。

    ```xml
    ...
      <steps>
        <step>
        </step>
      </steps>
    ...
    ```

    每个 `<steps>` 元素中至少要包含一个 `<step>` 元素。大多数DITA编辑器会在 `<steps>` 元素中自动插入一个 `<step>` 元素（在 `<step>` 元素中通常还会自动插入一个 `<cmd>` 元素）。

    在 DITA 中，操作步骤的内容也是高度受控的：每个操作步骤中都有一组特定的元素，这些元素必须按照特定的顺序排列。在 `<step>` 元素中，`<cmd>` 元素（读作“command”）是必选元素。`<cmd>` 元素主要用来说明用户需要执行的操作。在大多数情况下，一个 `<cmd>` 元素中只有一个句子，用来指导用户执行某项操作。

4. 在 `<step>` 元素中，插入一个 `<cmd>` 元素，并添加内容如下：

    ```xml
    ...
      <steps>
        <step><cmd>选择一个观看鸭子的地方。</cmd></step>
      </steps>
    ...
    ```

    按照最佳实践，一个 `<cmd>` 元素中应该只写一个句子，而且要使用主动语态，用来指导用户执行某项操作。

    使用 `<info>` 元素为 `<cmd>` 元素提供额外信息。在 `<cmd>` 元素之后、`<stepresult>` 元素之前，可以插入任意数量的 `<info>` 元素。

5. 在 `<cmd>` 元素的后面，插入一个 `<info>` 元素，并添加内容如下：

    ```xml
    ...
      <steps>
        <step>
          <cmd>选择一个观看鸭子的地方。</cmd>
          <info><p>通常，野外靠近水源的地方容易发现鸭子。</p></info>
        </step>
      </steps>
    ...
    ```

    `<info>` 元素中可以包含文本、安全信息、图片、表格等。和其他可以包含混合内容的元素一样，按照最佳实践，`<info>` 元素中的文本也应该放在 `<p>` 元素里，即使该元素中只有一个段落。
