# 合理使用子步骤

`<substeps>` 元素的用处很多，但请谨慎使用。

你如果发觉到处都是子步骤或者出现一些非常长、非常复杂的子步骤，可能就需要重新进行任务分析了。可能，你将核心任务拆分得还不够细致。你可以认真考虑一下是否可以将核心任务拆分成多个任务型主题。

还有一个明显的信号可以表明你的任务规划做得不合理：你编写了很多子步骤，但还是经常需要在这些子步骤中再插入一些子步骤。

子步骤只应在少数情况下使用，比如：

- 一个操作步骤很复杂，如果可以提供更多细节，用户会很受用。
- 目标受众中包括一些初级用户，如果可以提供更多指导，初级用户会很受用。大多数用户根据 `<cmd>` 元素中的内容就能理解整个操作步骤，但一些缺乏经验的用户可能需要根据子步骤中的细节信息才能完全理解。
  有些格式的文档可能不需要显示子步骤中的细节信息，除非用户特别指出。
- 内容不均衡的操作步骤。你偶尔会遇到这样的任务型主题：大多数操作步骤在细致水平上都差不多，但就有那么一两个操作步骤（尽管仍与其他步骤处于同一水平）需要添加更多细节。

有些使用子步骤的地方，可能改用 `<choice>` 和 `<choicetable>` 元素更合适。
