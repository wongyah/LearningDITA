# 关系表简介

在导图中，关系表主要用来定义主题与主题之间的关系。关系表也可以定义 DITA 主题和非 DITA 资源之间的关系。

通常，DITA 发布程序会根据关系表中的信息生成相关链接列表。关系表还有很多用途，具体取决于发布程序的能力大小和需要发布的文档格式。

!!! note "注意"
    关系表虽然叫“表”，也以表格的形式维护，但这张表格永远不会出现在发布后的文档中。

## 优点

与正文中的交叉引用相比，使用关系表维护主题间的关系可以提高各个主题的复用性。如果在主题中插入交叉引用，每个交叉引用的目标主题也必须插入到导图中，即使它们与当前导图毫不相干。如果目标主题中还有交叉引用，这些交叉引用的目标主题也必须插入到导图中，以此类推。使用关系表，可以让你摆脱这种循环依赖。

与正文中的交叉引用相比，关系表更容易维护。使用关系表，你可以在一个地方集中维护主题之间的关系网，不需要到各个主题中去逐个更新。

## 使用方法

导图和书籍导图中都可以插入关系表。一张导图或书籍导图中可以包含任意张关系表。

关系表中的**每一行**都包含一组相关关联的内容。例如，某一行里可能包含与某个系统组件有关的所有主题的主题引用，或与某项操作有关的所有主题的主题引用。

关系表中的**每一列**都包含一组**类型**相似的内容。关系表列的典型应用是区分概念型主题、任务型主题和参考型主题。如果还有其他主题类型，你可以为它们单独设置关系表列。有时候，可能还会设置一列专门放置指向外部信息的链接，比如网站。

!!! note "注意"
    在关系表中，列的顺序或相对位置无关紧要。

在关系表中，每个**单元格**可以包含一个或多个 `<topicref>` 元素。每个 `<topicref>` 元素引用一个主题文件。

## 示例

下面是一个简单的关系表示例：

|  概念型主题  |  任务型主题  |  参考型主题  |
|:---|:---|:---|
|  📄c_nourishment.dita  |  📄t_feeding.dita  |  📄r_food.dita <br/> 📄r_feeders.dita  |
|  📄c_shelters.dita  |  📄t_building.dita  |  📄r_houses.dita <br/> 📄r_feeders.dita  |

每一列的列标题表示该列的信息类型。第一个数据行填写的是与喂食有关的主题引用。第二个数据行填写的是与鸭舍有关的主题引用。在上面的示例中，还有两点需要注意：

- 一个 `<topicref>` 元素可以出现在多个数据行中。例如， `r_feeders.dita` 主题既与喂食有关，也与鸭舍都有关，两个的数据行里都有引用它的 `<topicref>` 元素。
- 每个单元格可以包含任意数量的 `<topicref>` 元素（包括零个）。

## 生成相关链接

生成文档时，DITA 发布程序会根据关系表创建相关链接。

- 在同一行中引用的主题之间，DITA 发布程序会生成相关链接。通常，相关链接位于主题的末尾，以列表的形式显示。
- 如果发布程序支持的话，还可以按照关系表列的定义对相关链接列表进行分组。

!!! note "注意"
    如果你想深入了解 `<reltable>` 元素及其子元素，请参见[《OASIS DITA 1.3 规范》：关系表](https://docs.oasis-open.org/dita/dita/v1.3/errata01/os/complete/part3-all-inclusive/langRef/base/reltable.html#reltable)。
